# v0.2.22 动画接缝与素材归属

## 目标与当前状态

本轮针对两个动态问题：呼吸或腿部摆动时人物接缝露出空隙，以及 Viola 抬腿时把朋友裙装一起拖动。v0.2.22 build 23 已安装，接缝工程检查和原生隐藏桌面窗口检查完成；本文区分常规动作审查与后续 toe-hook 专项复核。

## 素材归属和渲染处理

- 原始 PNG 未修改。运行时把前腿素材中属于朋友衣物的区域交回 seating 支撑层：审计记录前腿移除 8,615 个像素，seating 填回 10,026 个原本透明像素；恢复内容均为逐像素原样复制，未改动已有可见 seating 像素或保留的前腿颜色。两项数量统计口径不同，不应视为相等的素材块数量。
- 前腿与 seating 的注册偏移为 `(381, 6)`。审计确认前腿图像从 y=395 起的 RGBA 完全未变，因此鞋和较低腿部区域保留原图。
- 朋友裙装素材与 seating 使用同一张连续参考图。渲染时把裙装作为朋友支撑图的一部分，不再将其作为独立惯性布料层驱动；它跟随朋友自身支撑运动，不受 Viola 腿部摆动牵引。
- Viola 的身体、裙摆和大腿按同一呼吸驱动。seating、Viola 裙摆与大腿等内部拼接处保留原始像素的背衬，供呼吸和膝部运动时覆盖接缝；既有的朋友腿部衬层也向小腿运动范围后方延伸。

## 验证记录

素材归属审计位于 `build/motion-seams-v0.2.22/ownership/audit.json`。该审计记录前腿移除 8,615 个像素，并从原图精确填回 seating 中 10,026 个原透明像素；已有可见 seating 像素和保留前腿颜色未改动，62 张原始 PNG 均未改变。

最终普通动作姿势组覆盖桌面显示/隐藏两种模式共 18 个静态姿势。普通 720 帧审查在 toe-hook 背衬修复之前运行：每种模式各 720 帧，朋友支撑几何差异 0 帧，四张抽样隔离 PNG 差异 0；朋友自身呼吸在每种模式下均 720/720 帧产生变化。身体附件最大 Y 偏差约 `9.95e-14`。后续只改 recovery toe-hook 分支，不改变普通动作渲染。

toe-hook 恢复时曾发现背衬未跟随大腿变换。修复后将 join 与大腿皮肤背衬同步到实际大腿变换，并加入 `recoveryBackingCornerError` 诊断。最终 toe-hook 导出覆盖 20 个姿势、30 个角点测量，最大误差为 0；两张向前运动图已复核，先前的接缝残影不再可见。23 项 core checks 通过。证据包括 `build/motion-seams-v0.2.22/verification-summary.json`、`toe-hook-final/toe-hook-poses.json` 与 `core-checks.log`。

build 23 已安装并通过严格/深度签名验证。源码、bundle 和 profile manifest SHA-256 均为 `c292396db1d3a7fb994a24d71f1dcd02cc07be77fbf3b099944a1dfd334a3239`；包内 PNG 匹配，Mach-O code/data sections 匹配，安装过程未改配置。原生窗口已启动，桌面隐藏时截图确认没有旧接缝裂缝；诊断为 0.2.22、`showDesks=false` 且姿势可见。用户在启动后移动过窗口，因此不记录当前窗口精确位置。证据见 `install.log`、`installed-verification.json`、`native-diagnostics.json` 与 `native-config.json`。

普通动作范围已检查；朋友前臂下方保留的自然间隙是原有构图，不作为本轮接缝修复目标。物理键盘输入和整个人物美术的最终接受不在本次验证结论内。
